## Security cases (brief §10)

| Area | Evidence |
|---|---|
| Authentication | bcrypt (cost 12); 15-minute access JWT and 7-day refresh JWT in httpOnly, SameSite=Strict cookies (Secure in production); tampered token → 401; secrets only via environment (`.env` git-ignored, `.env.example` committed) |
| Role integrity | A `role: "admin"` field in the register body is ignored (test); roles are never read from client input |
| Authorization | Patient A → Patient B profile read/write/records/documents → 403; admin refused on patient and records endpoints; doctor access requires an existing appointment relationship; clinical reads are written to `audit_logs`; admin appointment list omits free-text `reason` |
| Input validation | zod on every route (unknown keys stripped, types coerced); `?q[$ne]=x` operator-injection → 400; regex search input escaped; MongoDB JSON Schema rejects invalid documents even if the API is bypassed (error 121 test); unique email index (error 11000 test) |
| Uploads | Allow-list PDF/PNG/JPEG/text with **content sniffing** (a PE executable renamed `.pdf` → 400); 4 MB limit; stored in GridFS with SHA-256; downloads only through an ownership-checked endpoint, `Cache-Control: private, no-store`, `nosniff`; no public URLs |
| Concurrency | 20 simultaneous bookings for one slot; plus 5 double-submits by one patient |
| Reliability | AI timeout 5 s with a safe fallback; AI service down → HTTP 200 with `degraded: true`; prediction service down → 503 with a UI message; offline PWA shell |
| Service-to-service | AI service requires `X-Internal-Secret` (constant-time compare, fails closed in production); Node sends only the question and an opaque id |
| PWA privacy | Service worker `NetworkOnly` for `/api/*`; an E2E test asserts no `/api/` or `/ai/` URL exists in any Cache Storage |

## Defects found by testing and fixed (not hidden)

- Booking screen defaulted to today even when every remaining slot had passed, leaving an unusable grid. Now advances to the first day with a free slot.
- After signing out, the next sign-in on the same device was redirected to the previous user's last page. Now cleared on explicit sign-out.
- Mobile horizontal overflow on the booking page (CSS grid track widened by the scrolling day strip). Fixed with `minmax(0, 1fr)`.
- Assistant composer overlapped the last message; translucent bars ghosted scrolled text (now solid).
- After a booking conflict the page could jump to another day (auto-advance treated picking a slot as no interaction), so the "already booked" slot the user had just lost was no longer on screen. This surfaced as an intermittent E2E failure; it was reproduced deterministically with mocked slot data (`tests/e2e/conflict-last-slot.spec.ts`, failing before the fix), fixed, and then verified with 10 consecutive clean runs of the full suite.
- Intermittent header-test failures were test-data exhaustion (random slots on one fixed day collided with earlier runs); the test now asks the API for a genuinely free slot.
- The AI service answered "Explain quantum computing" from the asthma passage (see `ai-methodology.md`).

## Known limitations

- Performance timing is 0 ms at 2,200 documents; examined documents are the evidence. A larger seed would show a time difference.
- Rate limiting is per serverless instance (in-memory), so it is a basic brake, not a global limit.
- Dark mode was implemented and judged from source and tokens but not screenshotted.
- Playwright runs on Chromium only (desktop and a mobile viewport); Safari/WebKit was not tested, including iOS PWA install behaviour.
- Clinic times are shown in UTC; there is no timezone handling.
- Booking assumes fixed 30-minute slots.
- Seeded accounts share one demo password (synthetic data only).
